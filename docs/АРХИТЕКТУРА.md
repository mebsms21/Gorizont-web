# Архитектура

## Переход на WordPress

На начало работы `/workspace` не содержал репозитория, исходников Next.js, макетов или экспортов. Поэтому перенос кода и сравнение с прежней реализацией не выполнялись: создан самостоятельный WordPress-проект, существующие материалы не удалялись.

Согласованная визуальная основа восстановлена из второго обсуждения: https://chatgpt.com/share/6af595a2-6a78-83ed-a53e-66c0b8ca0c22 . Изображения концепций 3.0, 3.1 и логотипа просмотрены и использованы при переработке. Это сайт веб-студии «ГОРИЗОНТ». Светлая система: белый и холодный серый фон, Manrope, графитовая типографика, оранжевые акценты и тема восхода. Уточнения: без декоративных стрелок, заставка при первом посещении, поднимающееся меню и последовательное появление контента.

Для демонстрации друзьям WordPress экспортируется в `preview/` и публикуется GitHub Pages. Админка и PHP остаются в основном проекте. На странице контактов интерактивный бриф скачивается локально; реальная отправка потребует настройки после переноса на PHP-хостинг.
## Разделение ответственности

WordPress хранит пользователей, страницы, контент, ревизии, медиатеку, меню и параметры. Собственная блочная тема `gorizont` отвечает за шаблоны и отображение. Плагин `gorizont-core` регистрирует бизнес-сущности. При смене темы услуги, проекты и контакты остаются в базе; плагин нужно оставить активным. При деактивации плагина записи не удаляются, но его типы и блоки перестают отображаться до повторного включения.

Ни активация темы, ни активация плагина не запускают импорт. Демо добавляется явным действием в панели или через WP-CLI. Импорт сохраняет существующие записи с совпавшим адресом, их тексты, обложки, параметры и контактные данные. Блокировка исключает одновременные запуски; незавершённый импорт можно продолжить повторным вызовом.

## Модель данных

| Сущность | Реализация | Где редактировать |
|---|---|---|
| Страницы | `page`, стандартные блоки | Страницы → Gutenberg |
| Услуги | `g_service`, REST, ревизии, обложка, отрывок | Услуги |
| Направления услуг | `g_service_type`, иерархия | Услуги → Направления |
| Портфолио | `g_project`, REST, ревизии, обложка, отрывок | Проекты |
| Типы проектов | `g_project_type`, иерархия | Проекты → Типы проектов |
| Контакты | опция `gorizont_contacts`, Settings API | ГОРИЗОНТ |
| Характеристики и SEO | зарегистрированные метаполя | Под редактором записи |
| Меню | `wp_navigation` | Внешний вид → Редактор → Навигация |
| Шапка, подвал, 404 | части и шаблоны блоков | Внешний вид → Редактор |

Контакты выводятся динамически: обновление в одном месте меняет все блоки контактов. Каталоги на главной и внутренних страницах читают опубликованные записи; вручную дублировать карточки не нужно. Порядок: `menu_order`, затем название. Фильтры и пагинация работают на сервере без JavaScript. Поисковые запросы ограничены 24 карточками на страницу.

## Дизайн-система

`theme.json` v3 — единственный источник палитры, семейства Manrope, размеров текста, основных отступов, сетки и кнопок. Настройки доступны в «Стили» редактора сайта. CSS добавляет композицию и адаптивные состояния; привязанные к палитре цвета используют CSS-переменные WordPress.

Белый `#FFFFFF`, холодный серый `#F4F5F7`, графит `#202833` и оранжевый `#FF6500`. Тёмные подписи кнопок читаются на оранжевом фоне; заголовок использует чуть более тёмный оранжевый для контраста. Локальный Manrope содержит кириллицу; OFL приложена. Запросов к Google Fonts при просмотре нет.

## SEO, скорость и защита

Семантические шаблоны с одним `h1`, метаописания, индивидуальные SEO-заголовки, canonical, Open Graph, штатный XML Sitemap WordPress. При включении Yoast, Rank Math, AIOSEO или SEOPress встроенные метатеги отключаются во избежание дублирования. Фильтры и страницы каталога с query-параметрами получают `noindex`. Organization JSON-LD выводится на главной после замены демонстрационных контактов.

WebP-превью, размеры изображений, `srcset` WordPress, отложенная загрузка карточек, локальный WOFF2 и отсутствие фронтенд-фреймворка уменьшают нагрузку. Результат производительности зависит и от хостинга; локальные цифры не гарантируют показатели production.

Метаполя используют nonce и проверку `edit_post`; настройки — `manage_options` и штатный Settings API. Входные значения очищаются, HTML экранируется, динамический SQL не формируется. REST сохраняет штатную авторизацию WordPress. Локальные пароли случайны и исключены из поставки. Редактор файлов WordPress выключен. В Nginx-примере закрыты конфигурация, XML-RPC, логи и PHP в uploads. На хостинге нужны HTTPS, обновления, резервное копирование и защита входа.

## Если будут предоставлены исходники Next.js

1. Сохранить исходное дерево и git-историю отдельной копией/веткой; не удалять и не перезаписывать.
2. Сопоставить маршруты с WordPress-страницами, услуги и проекты — с зарегистрированными типами.
3. Перенести тексты и изображения, сохранить лицензии, проверить размеры, alt и медиа-ссылки.
4. Перевести токены и компоненты в `theme.json`, паттерны и блочные шаблоны.
5. Подготовить карту 301-редиректов старых URL и проверить поисковую индексацию.
6. Проверить staging, резервную копию и план отката до смены production.
